# ani-steer

Claude Code 모드(플러그인). 사용자가 Claude를 교정한 말을 사례로 쌓고, 사다리로 올립니다.

사례 → 판단 → 교훈(판단 2개) → 규칙(3회) → 원칙(규칙 2개) → 근원 욕구(원칙 2개, 사용자가 확정)

- 판단(예/아니오)은 Jev(TypeSafe), 문장 정리는 Haiku가 합니다.
- 요청을 보낼 때 Jev가 해당되는 규칙(최대 3개)과 교훈(최대 2개)을 골라 그 요청에만 붙입니다. 규칙은 범위 안의 것을 모두(최대 16개) 판정하고, 교훈은 요청과 낱말이 겹치는 것을 판정합니다. 항상 붙는 것은 원칙과 확정된 근원 욕구뿐입니다.
- 프롬프트 위 한 줄 상태 표시, 오른쪽 패널(`/ani`), 승격 확인 카드.
- 교훈·규칙·지시는 말한 프로젝트에서만 붙고, 모든 프로젝트에 해당하는 것(응답 언어, 도구, 커밋 습관 등)은 어디서나 붙습니다. 어느 쪽인지는 저장할 때 Jev가 판정하고, `한 번에 관리`에서 `이 프로젝트` / `모든 프로젝트`로 바꿀 수 있습니다. 다른 프로젝트의 것은 `다른 프로젝트의 ○○ · 참고`에 프로젝트 이름과 함께 접혀 있고, 묻지 않습니다. `한 번에 관리`의 `모든 프로젝트로`로 어디서나 붙게 할 수 있습니다.
- Jev는 키가 둘 다 있으면 요청 판정은 TypeSafe(`TYPESAFE_API_KEY`)로, 지난 대화 찾기·교훈 범위 판정 같은 백그라운드 작업은 OpenRouter(`OPENROUTER_API_KEY`, 모델 `~typesafe/jev-latest`)로 보냅니다. 요청 판정은 TypeSafe로 직접 가는 쪽이 이 컴퓨터에서 약 0.2초 빠릅니다. 한쪽이 거절하면(잔액 부족, 잘못된 키) 다른 쪽으로 넘어갑니다. 키가 하나뿐이면 전부 그쪽으로 갑니다. 어느 쪽으로 붙었는지는 `설정` 탭의 `Jev 연결 (요청 TypeSafe · 백그라운드 OpenRouter)`에 보입니다.
- 한 프로젝트에 묶인 교훈·규칙은 세션 시작 때 하나씩 한 번 Jev가 다시 봅니다. 어느 프로젝트에서나 통하는 작업 습관(요청을 읽는 법, 고칠 범위, 확인·보고 방식)이고 그 프로젝트의 코드·도구·파일·디자인·소재·사람을 말하지 않으면 모든 프로젝트로 옮깁니다. 두 질문이 모두 그렇다고 해야 옮깁니다. 사용자가 직접 범위를 정한 것은 다시 보지 않습니다.
- 교훈 개수에 한도가 없습니다. 요청마다 Jev가 관련 있는 것을 골라 교훈은 최대 2개, 규칙은 최대 3개만 붙이므로, 쌓인 수가 요청을 무겁게 하지 않습니다. 예전에 한도 때문에 보관된 교훈은 한 번 되살립니다.
- 지난 대화 찾기 중 Jev 호출이 끊기거나 5xx·429가 오면 1초·4초·15초 뒤 다시 시도하고, 그래도 안 되면 멈추며 이유(`HTTP 503` 등)를 보여 줍니다. `이어서 찾기`로 이어 갑니다.
- 프로젝트 기록이 생기기 전에 저장된 지시는 대화 기록에서 저장된 시각의 요청을 찾아 그 세션의 프로젝트를 채웁니다(예약 작업이 보낸 요청 포함). 못 찾으면 `출처 모름`으로 남고 다시 찾지 않습니다.
- 이 컴퓨터의 모든 피드백을 한곳에 보여 줍니다. 예전 ani 플러그인의 기록(`~/.ani/patterns`)도 처음 한 번 가져옵니다: S는 모든 프로젝트의 교훈, 정리되지 않은 F는 그 F를 말한 프로젝트의 교훈, S로 묶인 F는 그 S의 사례가 됩니다. 원본 파일은 건드리지 않고, 여기서 잊은 항목은 다시 가져오지 않습니다. 프로젝트는 `owner/repo`, 폴더 이름, Windows 경로 중 무엇으로 기록됐든 마지막 이름이 같으면 같은 프로젝트로 봅니다.
- `사례` 탭에서 이 프로젝트의 사례는 앞뒤 맥락까지 펼쳐 보여 주고, 다른 프로젝트의 사례는 교훈처럼 한 줄(내가 한 말 · 프로젝트 · 날짜)로 보여 줍니다. 맥락은 저장소에 그대로 남아 Jev와 Claude가 씁니다.
- 설치하기 전의 교정도 사례가 됩니다. `사례` 탭의 `지난 45일 대화에서 사례 찾기`를 누르면 Claude Code 대화 기록(`~/.claude/projects/*.jsonl`)에서 사용자가 직접 보낸 요청만 읽고, Jev가 10개씩 묶어 교정인지 판정합니다. 요청마다 앞뒤 대화(이전 요청 3개, 에이전트의 답과 실제로 한 작업, 다음 요청 2개)를 함께 보여 주므로, 질문으로 한 교정(`X 아니지???`)이나 다음 지시와 섞인 교정도 찾습니다. 교정이면 사례가 되고, 실시간 교정과 같은 사다리를 탑니다. 읽은 기록은 세션 단위로 표시해 두어서, 중간에 멈추면 다시 눌러 이어서 할 수 있습니다. 예전 기준으로 찾은 경우 `새 기준으로 다시 찾기`가, 45일을 다 읽은 뒤에는 그 이전 대화를 찾는 버튼이 나옵니다.
- 사용자가 친 말만 사용자의 말로 기록합니다. 앱 알림(`<system-reminder>`, `<ci-monitor-event>`, `<task-notification>`), 예약 작업, 다른 에이전트·세션이 보낸 지시(대화 기록의 `origin`이 `human`이 아닌 것), 다른 프로그램이 시작한 세션(`claude -p`, SDK), 앱 도우미의 역할 지시(`You are a ...`)는 사례·지시가 되지 않습니다. 붙여 넣은 터미널 조각은 떼어 냅니다. 이미 그렇게 저장된 지시는 대화 기록에서 출처를 찾아 따로 빼 둡니다.
- 옛 ani 기록은 영어 요약이 사용자의 말 자리에 있었습니다. 세션이 시작될 때 몇 개씩 한국어로 다시 쓰고, 사용자가 실제로 한 말(기록의 `> user:` 발췌, S는 그 S를 만든 F의 발췌)로 바꿉니다.
- Claude 자동 메모리(`~/.claude/projects/*/memory/*.md`)의 `feedback` 노트도 한국어 교훈으로 가져옵니다(세션 시작마다 12개까지). 노트를 쓴 폴더의 프로젝트에 붙고, 홈 폴더에서 쓴 노트는 모든 프로젝트에 붙습니다. 원본 파일은 건드리지 않습니다.
- 같은 판단은 말과 프로젝트가 달라도 묶입니다. 사례마다 Haiku가 고칠 작업 습관을 한 단계 일반화해 적고(예: `지정된 범위를 넓혀서 해석함`), Jev가 그 습관이 같은지 판정합니다. 두 프로젝트에서 같은 실수가 나오면 모든 프로젝트의 교훈 후보가 됩니다. 교훈 후보는 `교훈` 탭에서 `교훈으로` / `아님`으로, 같은 교정이 3번 쌓인 교훈은 `규칙` 탭에서 `규칙으로` / `아직 교훈으로`로 확정합니다. 자동으로 확정되는 것은 없습니다.

## 설치

```
/plugin marketplace add ThingsLikeClaude/ani-steer
/plugin install jev-steer@ani-steer
```

Jev(TypeSafe) 키가 필요합니다. 키가 없으면 첫 실행 때 프롬프트 위에 안내 카드가 뜨고, `키 설정하기`를 누르면 `/jev-steer:ani-key`가 숨김 입력창으로 키를 받아 `~/.claude/settings.json`의 `env.TYPESAFE_API_KEY`에 저장합니다. 키는 채팅에 남지 않습니다. macOS · Linux · Windows 모두 지원하며 jq 같은 외부 도구는 필요 없습니다.

## 저장

`$.store` (Claude Code 플러그인 저장소, JSON). 교훈 `cards`, 사례 `feedbackLog`, 지시 `requirements`, 원칙 `principles`, 근원 욕구 `needs`.
